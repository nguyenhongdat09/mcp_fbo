## 1) BỐI CẢNH HỆ THỐNG

Pipeline hiện tại:
```
FS event (watchdog)
  -> GraphUpdateHandler.on_any_event
  -> incremental_update_file(path)
  -> KuzuIndexStore.update_single_node(node, edges)
  -> (daemon) on_node_updated hot-reload RAM
```

Watcher bật khi:
- MCP lần đầu gọi tool cần Kuzu (`start_watcher_for_project`)
- Daemon CLI
- `python xml_graph_cli.py watch --ref $REF`

Kuzu local: `C:\KuzuDB\<base64(project_root)>\.fbograph\kuzu`  
(KHÔNG ghi `.fbograph` lên share dự án)

Edge nghiệp vụ quan trọng (phải giữ sau incremental):
- `GRID_MASTER_DETAIL`
- `RETRIEVE_DATA_SOURCE`
- `LOOKUP_REFERENCE`
- `ENTITY_INCLUDE`, `PARAM_ENTITY_USE`
- `COMPANION_FILE`
- `SQL_TABLE_USE`, `SQL_PROC_CALL` (đã có một phần)

Canonical identity đã có sẵn (`canonical_path`, `alias_of`, `add_rewrite_edge` trong full build). Incremental phải **tương thích** mô hình đó.

## 2) TRIỆU CHỨNG / BUG ĐÃ XÁC NHẬN TRONG CODE

### Bug A — Sửa file → MẤT edge FBO (nghiêm trọng nhất)

`update_single_node`:
1. `DETACH DELETE` node → xóa **HẾT** edge vào + ra
2. CREATE lại node
3. Chỉ CREATE lại edge do `incremental_update_file` truyền vào

Nhưng `incremental_update_file` **chỉ** tạo:
- `SQL_TABLE_USE`
- `SQL_PROC_CALL`

**Không** tạo lại:
- `GRID_MASTER_DETAIL`
- `RETRIEVE_DATA_SOURCE`
- `LOOKUP_REFERENCE`
- `ENTITY_INCLUDE` / `PARAM_ENTITY_USE` / `COMPANION_FILE`

Repro kỳ vọng (SP2261):
```powershell
$REF = "\\172.168.5.14\CustomerPro\FBO\PHELA\SP2261\App_Data\Controllers\Grid\CPDetail.xml"

# Baseline OK sau full build:
python xml_graph_cli.py query -t radar "MATCH (voucher:XmlFile)-[r1:Rel]->(detail:XmlFile)-[r2:Rel]->(flt:XmlFile) WHERE flt.relative_path = 'Filter\\CPRequestFilter.xml' AND r1.edge_type = 'GRID_MASTER_DETAIL' AND r2.edge_type = 'RETRIEVE_DATA_SOURCE' RETURN voucher.relative_path, detail.relative_path, flt.relative_path LIMIT 10" --ref $REF --direct
# -> Dir\CPTran.xml / Grid\CPDetail.xml / Filter\CPRequestFilter.xml

# Sau khi watcher incremental-update Grid\CPDetail.xml (sửa nhỏ / touch file):
# Cùng query trên DỄ thành [] vì DETACH DELETE đã xóa GRID + RETRIEVE.
```

### Bug B — Xóa file không xóa node Kuzu

`on_any_event` luôn gọi `incremental_update_file(src_path)`.  
File đã xóa → parse fail → return None → **node cũ vẫn còn** trong Kuzu (node ma).

### Bug C — Đổi tên / move lệch graph

Watchdog `moved`/`renamed`:
- `event.src_path` = path cũ
- Có thể có `event.dest_path` = path mới

Hiện tại chỉ xử lý `src_path` như “sửa” → không xóa node cũ, node mới có thể thiếu / trùng.

### Bug D — Debounce global 1 giây

`last_triggered` dùng chung mọi file.  
Đổi nhiều file trong 1 giây → event sau bị bỏ.

Cần debounce **theo file** (hoặc queue + flush), không theo global timer.

### Bug E — Cache RAM MCP không hot-reload

`daemon.py` có `on_node_updated` → `graph.add_node`.  
MCP `start_watcher_for_project` **không** truyền callback → `_graph_cache` có thể stale sau watcher ghi Kuzu.

Query `search/navigate/dependents` (load graph RAM) có thể thấy data cũ;  
`radar` (Cypher thẳng Kuzu) thấy data mới hơn.

### Bug F — Edge incremental gắn `source_id = alias_of` nhưng DELETE theo `node_id`

Khi update alias file (Config/Fields/...), DETACH DELETE node alias, nhưng edge tạo từ canonical id — dễ lệch.  
Cần mô hình rõ: update node vật lý nào, edge rewrite về canonical như full build.

### Bug G — SQL edge target thường không phải XmlFile

`update_single_node` chỉ CREATE Rel nếu `MATCH XmlFile {node_id: target_id}` tồn tại.  
`SQL_TABLE_USE` target = tên bảng → thường **không** tạo được edge SQL dù code “có append”.  
(Full build có thể khác — tự kiểm tra và thống nhất.)

## 3) YÊU CẦU CHỨC NĂNG (ACCEPTANCE)

Sau khi sửa, với project bất kỳ (không hardcode CPDetail):

### 3.1 Sửa nội dung file (.xml/.ent/.txt trong scope)
- Node được parse lại (fields, js_text, sql_text, grid_refs, lookup_refs, js_blocks…)
- Edge **đi ra** từ node (hoặc canonical) được rebuild đúng:
  - `RETRIEVE_DATA_SOURCE` từ `g.showForm(...)` trong js_blocks
  - `GRID_MASTER_DETAIL` từ grid_refs (+ pattern JS nếu full build có)
  - `LOOKUP_REFERENCE` từ lookup_refs
  - `ENTITY_INCLUDE` / `PARAM_ENTITY_USE` nếu có
  - SQL edges theo quy ước thống nhất với full build
- Edge **đi vào** từ node khác (vd CPTran → CPDetail) **KHÔNG bị mất** vì sửa CPDetail
  - Hoặc: sau update, các edge inbound được khôi phục / không xóa inbound khi DETACH

### 3.2 Thêm file mới
- Tạo node mới trong Kuzu
- Tạo edge outgoing đúng
- Node khác trỏ tới controller mới (nếu đã có reference) vẫn resolve được qua `find_node_by_controller_name` / canonical

### 3.3 Xóa file
- Xóa node tương ứng khỏi Kuzu
- Xóa edge liên quan (DETACH DELETE node là OK **khi xóa file**)
- Không để node ma

### 3.4 Đổi tên / move
- Xóa node path cũ
- Tạo/cập nhật node path mới
- Edge nghiệp vụ phản ánh path/canonical mới
- Không trùng 2 node cùng logical controller một cách sai

### 3.5 Debounce
- Đổi nhiều file liên tiếp đều được xử lý (không drop vì timer global)

### 3.6 Cache
- Sau incremental: invalidate hoặc hot-reload `_graph_cache` / `_store_cache` phù hợp cho **cả MCP và daemon**
- Query sau đó thấy data mới (không chỉ radar)

### 3.7 Không phá full build
- `GraphBuilder.build()` / `build_and_save_graph` vẫn đúng như hiện tại
- Canonical / alias logic đã có vẫn dùng lại, đừng viết song song 2 mô hình

## 4) GỢI Ý HƯỚNG THIẾT KẾ (bạn được tự chọn, miễn đúng)

Ưu tiên một trong các hướng sau (hoặc kết hợp tốt hơn):

**Hướng 1 — Soft replace node, không DETACH toàn bộ**
- Update properties node
- Chỉ xóa + tạo lại **outgoing** Rel của node (filter theo source_id)
- Giữ nguyên **incoming** Rel từ node khác

**Hướng 2 — Incremental recompute edges có lookup graph**
- Load tối thiểu index path→node_id / canonical từ Kuzu
- Dùng lại `find_node_by_controller_name`, `add_rewrite_edge` logic như full build
- Rebuild full bộ outgoing edges (GRID/RETRIEVE/LOOKUP/ENTITY/SQL…) cho node vừa sửa

**Hướng 3 — Dirty queue + partial rebuild**
- Gom file dirty trong N giây
- Rebuild edges cho tập node bị ảnh hưởng (file đổi + neighbor 1 hop nếu cần)
- Fallback rebuild full nếu dirty quá lớn

**Xóa / rename:** xử lý riêng event `deleted` / `moved` (đừng gọi parse path đã mất).

**Debounce:** `dict[path] -> last_time` hoặc queue + worker.

**MCP cache:** truyền `on_node_updated` giống daemon, hoặc invalidate `_graph_cache[graph_dir]` sau mỗi update thành công.
