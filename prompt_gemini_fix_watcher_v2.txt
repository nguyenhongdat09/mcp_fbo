## 1. BẰNG CHỨNG KIỂM TRA THỰC TẾ

### Lỗi nghiêm trọng: watcher không ghi được nếu MCP đã mở Kuzu read-only

Quy trình đã chạy:

1. Query `mcp_query_radar` trước, khiến Kuzu được mở `read_only=True`.
2. Gọi `incremental_update_file(CPDetail.xml, ...)`.
3. Kết quả:

```text
[CodeGraph] incremental_update_file error for ...\Grid\CPDetail.xml:
Connection exception: Cannot execute write operations in a read-only database!
updated: None
```

Nguyên nhân trong `KuzuIndexStore.__init__`:

```python
cache_key = str(self.db_path).replace("\\", "/").lower()
if cache_key not in _db_instances:
    db = kuzu.Database(str(self.db_path), read_only=read_only)
    conn = kuzu.Connection(db)
    _db_instances[cache_key] = (db, conn)

self.db, self.conn = _db_instances[cache_key]
```

`_db_instances` chỉ cache theo path, không phân biệt connection read-only/read-write.
Nếu connection read-only được tạo trước, `KuzuIndexStore(db_path)` dùng cho watcher sẽ tái sử dụng connection read-only.

Đây là case thực tế của Cursor MCP: MCP query trước, watcher chạy trong cùng process sau đó.

### Lỗi Companion query

Incremental update trong process sạch có chạy, nhưng log:

```text
[CodeGraph] Warning: failed to rebuild companion edges ...:
Parser exception: Unknown operation '!='
(you probably meant to use '<>', which is the operator for inequality testing.)
```

Query hiện tại dùng:

```cypher
AND n.node_id != $nid
```

Kuzu yêu cầu:

```cypher
AND n.node_id <> $nid
```

### Phần đã pass

Khi chạy incremental trong process sạch, mở write connection trước:

```text
updated: Grid\CPDetail.xml js=5
```

Sau đó query 2 hop vẫn có:

```text
Dir\CPTran.xml -> Grid\CPDetail.xml -> Filter\CPRequestFilter.xml
```

Như vậy logic backup/restore inbound và recompute outbound đi đúng hướng; cần sửa lifecycle connection và các lỗi còn lại.

## 2. YÊU CẦU SỬA CONNECTION / LOCK

### Mục tiêu bắt buộc

Trong cùng một process:

1. Mở/query Kuzu read-only trước.
2. Sau đó watcher cập nhật file.
3. Incremental update vẫn phải ghi được.
4. Query tiếp theo phải đọc thấy dữ liệu mới.

### Không được sửa kiểu giả

- Không được chỉ `del _db_instances[key]` trong khi object DB/connection cũ vẫn còn reference.
- Không được bắt exception rồi báo “thành công”.
- Không được buộc người dùng restart Cursor/MCP.
- Không được rebuild full sau mọi event.
- Không được mở đồng thời read-only và read-write trên cùng DB theo cách gây lock.

### Thiết kế khuyến nghị

Hãy tạo API quản lý connection rõ ràng trong `kuzu_index.py`, ví dụ:

```python
def close_cached_database(db_path: Path) -> None:
    ...

def get_cached_database_mode(db_path: Path) -> Optional[str]:
    ...
```

Hoặc thiết kế tương đương.

Khi cần writer:

1. Invalidate `_store_cache`, `_graph_cache`, `_kuzu_stores` có liên quan.
2. Đóng/release connection read-only cũ an toàn.
3. Mở lại DB bằng `read_only=False`.
4. Thực hiện transaction/update.
5. Sau update, reader sau đó được mở lại từ dữ liệu mới.

Hãy kiểm tra API thực tế của package `kuzu` đang cài để close/release đúng (`Connection.close`, `Database.close`, hoặc giải phóng reference + GC nếu API không có).
Không được đoán tên method.

### Đồng bộ thread

MCP query và watcher là các thread trong cùng process. Cần có lock per-database hoặc cơ chế single-owner:

- Query không được dùng connection trong lúc writer đang thay mode/update.
- Hai event watcher gần nhau không được tranh writer.
- Lock chỉ theo từng DB/project, không khóa toàn bộ mọi project.
- Dùng `threading.RLock`/Lock theo normalized db path hoặc thiết kế tương đương.

## 3. SỬA COMPANION

Đổi toán tử Kuzu:

```cypher
n.node_id != $nid
```

thành:

```cypher
n.node_id <> $nid
```

Sau đó chạy query thực tế để xác nhận không còn warning.

Ngoài ra kiểm tra:

- Không tạo duplicate `COMPANION_FILE`.
- Không companion nhầm các controller chỉ tình cờ cùng normalized basename nhưng sai logical folder/group.
- Hai chiều phải nhất quán với full build hiện tại.

## 4. RÀ SOÁT CÁC LỖI CÒN LẠI

### 4.1 Path separator trong `sort_priority`

Code hiện tại kiểm tra:

```python
if "grid/" in rp:
if "dir/" in rp:
```

Nhưng `relative_path` Kuzu dùng backslash (`Grid\CPDetail.xml`).
Chuẩn hóa path trước khi so sánh:

```python
rp = rp.replace("\\", "/").lower()
```

Không phụ thuộc separator Windows.

### 4.2 Alias update và duplicate edge

Incremental của file alias có thể tạo edge với:

```python
source_id = node.alias_of
```

Nhưng `update_single_node` chỉ `DETACH DELETE` node vật lý `node.node_id`.
Nếu `node.alias_of != node.node_id`, outgoing edge cũ của canonical không bị xóa, rồi edge mới được CREATE thêm — có nguy cơ duplicate/stale.

Phải thiết kế rõ:

- Node vật lý vẫn update properties theo `node_id`.
- Edge nghiệp vụ được gắn canonical theo mô hình full build.
- Khi recompute edge từ alias, chỉ thay đúng nhóm edge do physical source đó đóng góp, hoặc rebuild deterministic cho canonical group.
- Không xóa nhầm edge do alias khác/canonical source khác đóng góp.
- Không tạo duplicate edge sau khi save cùng file nhiều lần.

Nếu schema `Rel` hiện không lưu `parsed_from_source`, hãy dùng meta hoặc bổ sung cách xác định ownership nhất quán với `add_rewrite_edge` full build.

### 4.3 Inbound restore không duplicate self/inbound-outbound

Nếu có edge self-loop hoặc edge vừa là outgoing của canonical source và inbound vào node được replace, backup + recreate outbound + restore inbound có thể duplicate.

Trước khi CREATE edge:

- Dedupe theo `(source_id, target_id, edge_type, meta/ownership phù hợp)`.
- Save cùng file 3 lần không làm tăng số edge.

### 4.4 Delete / move canonical hoặc alias

Khi xóa/rename:

- Xóa node cũ.
- Re-evaluate canonical identity của logical group.
- Nếu canonical node bị xóa nhưng còn alias readable, phải chọn canonical mới và rewrite/rebuild edge liên quan.
- Không để `alias_of` của node còn sống trỏ tới node đã xóa.
- Không để inbound edge biến mất vĩnh viễn khi rename controller.

### 4.5 Cache MCP

`mcp_tools.start_watcher_for_project` hiện gọi:

```python
start_watcher(controllers_dir, graph_dir)
```

không truyền `on_node_updated`.

`invalidate_project_cache()` cần xử lý đủ:

- `query.engine._store_cache`
- `query.engine._graph_cache`
- `query.engine._last_sync_times` nếu cần
- `mcp_tools._kuzu_stores`
- `storage.kuzu_index._db_instances`

Không để `_kuzu_stores` giữ lại store/connection cũ sau invalidate.

Tránh import cycle; có thể dùng callback được truyền từ `mcp_tools` hoặc một connection manager chung.

### 4.6 `.f`

Watcher hiện chỉ nhận `.xml/.ent/.txt`, full build có `.f`.
Hãy quyết định và triển khai nhất quán:

- Nếu `.f` cần được index: watcher phải nghe `.f`, xử lý pairing `.xml/.f` đúng như full build.
- Nếu cố ý không watch `.f`: ghi rõ lý do và acceptance; không tuyên bố “mọi file” được cập nhật.

Ưu tiên hỗ trợ `.f` để graph phản ánh file mới/xóa/rename.
